# Project-first UI

## Workspace refinement — October 2026

The desktop workflow now lives in a persistent left rail, leaving more room above the fold for the current task. At tablet widths it becomes a compact horizontal bar; phone widths retain all four step labels. The header shows whether the current study has unsaved changes, and a skip link moves keyboard users directly to the workspace. Research-only studies return from Review to Setup consistently.

Projects has a searchable list with an explicit no-results recovery action. Setup replaces introductory sidebar copy with the actual study goal, planned audience, source counts, and links to unfinished setup. These indicators describe authoring readiness; Review remains the authority for validation and permission checks.

Audience puts generation, progress, and recoverable errors before the form. Allocation bars complement numeric segment counts, selected user/buyer options explain their roles, and country/profile editors group related controls. Settings separates connections from run limits, shows a concise configuration summary, and keeps model customization available in its disclosure.

Review leads with readiness and a compact summary of materials, people or research scenarios, time, and cost. The start action waits for login checks and requires current persona profiles after audience edits, including changes that leave the persona count unchanged. Reports have a clearer metric header, section shortcuts, readable comparison tables, and a dedicated export area. Shortcuts open folded sections and move keyboard focus to their headings; exports retain portable, static content. Persona inspection leads with recorded actions and provides Journey, Opinions, and Profile shortcuts. Empty social sections stay folded.

Activity now keeps all filters together, including profile attributes. Removable chips show active selections, and clearing filters also clears the profile selection, so an empty feed has an obvious recovery action. Saved run history and the background simulation dock retain their independent scrolling and spacing above fixed action bars.

Verification uses disposable Electron profiles and scripted model responses. The full journey plus UI, projects, audience, providers, profiles, Figma, comparison, research, completion, background, point-of-interest, and text smoke suites cover the affected workflows. The UI smoke also checks project search and visible workflow controls at 320, 768, 1024, and 1440 pixels; comparison/research checks exercise section shortcuts and the research-only back path. Audience checks cover both changed persona counts and stale profiles with unchanged counts. See `app/test-results/` for captured screens.

## Existing behavior and guarantees

The desktop app follows the supplied `brand.md`: Paper canvas, Olive actions, the supplied logo, local Inter, quiet rules, and no decorative shadows. The project chooser is a simple list with a single create action; project management lives in a compact dropdown anchored to a centered, 40px overflow button. It closes on outside clicks, focus leaving the control, window blur, Escape, or selecting an action. Tab moves through its actions; Escape and returning from a dialog restore focus to the overflow button. The active project reopens on launch. Returning to the list keeps the draft; switching projects retains the existing save/discard/cancel protection.

Within a project, Setup → Audience → Review → Simulation establishes the journey. Settings remain available separately. Setup leads with product, test URL and goal; login, network and reset controls are progressively disclosed. Existing safety confirmation and run review stay intact. Each screen has a visible way back. Configured projects can revisit any step.

Settings keeps provider and model dropdowns for each task in the collapsed Model choices accordion, with recommended models and a custom-model option. When only one provider is connected, tasks assigned to unavailable providers use that provider's defaults. This also applies when reopening older projects; valid model choices are preserved. With several connected providers, Gnomi keeps explicit choices rather than guessing a replacement. Missing-key errors refer to the selected AI provider and point to Settings.

The final Simulation step puts the simulation map beside a compact status and progress panel on wide screens, with audience activity below. Narrow screens stack status and map. Progress is driven by recorded work. The map explains people, product areas and connection types, supports focusing on a person or area, and can replay earlier rounds independently of the activity feed. Product use and friction are visible by default; conversation and opinion links are opt-in to keep large audiences legible. Small audiences use a stable labeled layout. Layout motion can be frozen without stopping incoming results.

Progress counts eligible persona/product sessions, planned discussion rounds and report milestones. Finishing an individual goal is not equivalent to finishing discussion. Reports appear only after the run ends; a successfully loaded finished report completes the meter. Stopped and interrupted simulations retain their partial progress and can still show their available report. Elapsed time and recorded cost are separate from progress, which is not a time estimate. A failed report load has an explicit retry action. On successful completion, the report opens once; later saved-report updates preserve the user's chosen view.

Audience activity connects actions, reactions and associated evidence into readable moments. Actions and persona quotes remain visible together; failures and friction stay prominent. All events retains the detailed audit trail. Pause updates freezes the feed for reading while the simulation continues, and resuming reveals buffered updates. Persona names and avatars open the full profile; activity details open only on click/tap or keyboard activation, close with Escape, and retain links to exact evidence. Full audience conversation threads and the persona roster are available below the primary feed. Audience attributes filter activity and the roster; report filters remain available in the completed report. Simulation/report tabs appear after completion and support arrow keys, Home and End.

Design contract: preserve the Paper/Olive palette, local Inter and quiet borders; keep the graph before the feed; avoid overlapping controls, truncated primary quotes, false precision about time remaining, and moving content while a user is reading. Verify starting, live, reporting, finished, stopped/interrupted, blocked, empty and failure states. Layouts must fit 320, 768, 1024 and 1440px, with keyboard-accessible controls and reduced-motion support.

The packaged app loads its logo and Inter font locally. HTML/PDF exports embed both assets so reports remain portable and make no network requests. The existing screenshot size budget is unchanged.

Acceptance: create/open/switch projects; remember selection across reload and restart; preserve dirty drafts; complete a scripted run; inspect persona evidence from names and avatars; expand timeline details only on click/tap or keyboard activation; filter and clear; stop a run; view report; render without overflow at 320, 768, 1024 and 1440 px; respect reduced motion. Use disposable Electron data and scripted personas for verification.

Run `npm run smoke:ui -w @gnomi/app` for the focused journey, brand-asset, timeline, restart and responsive checks. Screenshots are written to `app/test-results/revamp-*.png`. Existing `smoke`, `smoke:projects`, `smoke:profiles`, `smoke:budget`, and `perf:swarm` scripts follow the updated navigation.

Run `npm run smoke:providers -w @gnomi/app` for provider assignment, existing-project recovery, audience generation, model customization and responsive model controls. It uses disposable keys and scripted responses, with screenshots in `app/test-results/provider-models-*.png`.

Audience preparation has three explicit steps: define the audience, generate its personas, then review the run. A prominent Generate personas action appears above the segment editor. Review stays disabled while a setup task is running or personas are missing or stale; Setup directs an audience with no personas back to the builder. The built-in-persona shortcut remains available when no audience is configured.

Both generation tasks display local SVG profile illustrations with gentle CSS motion, disabled for reduced-motion preferences. Audience planning is indeterminate. Persona generation shows the engine's completed/total count inside the illustration, plus a progress bar; that total covers the new or changed personas being written. Full draft progress shows “Finishing touches” until validation and saving complete. Errors clear the loading state and leave the form available for retry.

Run `npm run smoke:audience -w @gnomi/app` for loading, required generation, progress, failure/retry, completion, narrow layouts, and reduced motion. The test holds requests and injects progress messages to inspect intermediate UI states, then releases requests to the real scripted engine. It uses disposable data and no paid model calls. Screenshots are saved as `app/test-results/audience-*.png`.

Run `npm run smoke:completion -w @gnomi/app` for default graph visibility, report gating, event-driven progress, responsive running screens, report refresh races and navigation after completion. `npm run perf:swarm -w @gnomi/app` checks live graph updates with 200 personas and thousands of connections.
